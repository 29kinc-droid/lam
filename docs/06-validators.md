# Phase 6 — 검증기 3종 스펙

현재 파이프라인에는 Notion 설계의 "LLM 호출 #1(의도파악+쿼리재작성)"이 없고 단일 LLM 호출만 있으므로, 입력단 검증은 "재작성된 쿼리" 대신 **툴 호출 인자**를 검증하는 형태로 구현한다(플랜 문서 표현 "재작성된 쿼리/툴 인자" 중 실제로 존재하는 대상).

## 1. 입력단 — `validators/input_validator.py` (규칙 기반)

- `validate_tool_call(tool, call) -> list[str]`: 툴의 JSON Schema(`parameters`)를 기준으로 필수 필드 누락, 알 수 없는 인자, 타입 불일치를 검사.
- 실패 시 툴을 실행하지 않고 오류 메시지를 tool 결과로 돌려줘서 모델이 인자를 고쳐 재시도하게 한다(`max_rounds` 소모).

## 2. 출력단 — `validators/output_validator.py` (동일 모델 재호출)

- RAG/그래프로 가져온 근거(evidence)가 있을 때만 실행(근거 없으면 검증할 대상이 없으므로 스킵 — 매 턴 여분 호출 비용 방지).
- 별도 프롬프트로 같은 `qwen2.5:7b-instruct`를 호출해서 "답변이 근거에 없는 내용을 단정하는지" 확인. `OK` 또는 `ISSUE: <이유>` 형식으로만 답하도록 지시.

## 3. 실행후 — `validators/post_exec_validator.py` (규칙 기반)

- 응답 텍스트에서 `[출처명]` 형태의 인용 표기를 정규식으로 추출해, 실제 이번 턴에 검색된 RAG 소스 목록에 있는지 대조. 근거가 있을 때만 실행(citation 검사도 근거가 없으면 오탐 방지를 위해 생략).
- 시스템 프롬프트에 "관련 문서를 인용할 때는 [파일명] 형식으로 출처를 표시하라"는 지시를 추가해 검증 가능하게 함.

## 통합

`controller/loop.py`: 툴콜 없는 최종 텍스트 응답이 나오면 위 2·3번 검증을 실행. 문제가 발견되고 아직 라운드가 남아있으면, 검증 결과를 tool 메시지 형태로 대화에 추가해 모델이 스스로 고치도록 하고 루프를 반복한다(`max_rounds`로 제한). 라운드가 소진되면 마지막 응답을 그대로 반환한다(무한 루프 방지가 우선, 완벽한 차단이 목표가 아님 — 프로토타입 단계).
